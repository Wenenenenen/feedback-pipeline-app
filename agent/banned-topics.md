## 难度要求

只允许「困难」「地狱」：

- 困难：需要整合多个模块/系统约束，做关键设计取舍，处理复杂状态、兼容性、权限、并发、性能或异常链路。
- 地狱：决策复杂度极高，需求开放或约束隐蔽，需要架构级判断、多步复杂调试验证，或正确性依赖大量边界场景，SOTA 模型也难以成功交付。

不合格（过于简单）的典型特征，满足两条及以上即不合格：
- 意图明确，主要沿已有模式做机械修改或局部实现；
- 改动虽多但模式高度一致、核心判断很少；
- 不涉及跨模块数据流或实现决策；
- 没有需要处理的边界条件与约束。

## 其他硬性约束

- 禁止使用 docker 出题（题目不能要求用 docker 搭环境或交付）。
- 同一仓库下不得出现与已有题目雷同的「项目 + 需求」。
