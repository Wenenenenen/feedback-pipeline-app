# Feedback 写作规范

适用于 Feedback、评分理由。后端会按本规范做规则检查（口吻、原分依据、代码锚点、质检会打回的表达），不通过的 Feedback 不能进入录屏环节。

## 核心标准

Feedback 不要求长，也不套固定模板，关键是读起来像懂行的人对这次任务的直接判断，并且过程、产物、证据、原分四件事能互相对上。只看这段文字，不知道题目名也能明白：模型具体做了什么，最终代码哪里有问题（或为什么确实完成），为什么会造成这个结果，问题在最终提交里是否还在，以及这些事实为什么对应这个分数。

四个标准缺一不可：

1. 有实际过程：模型做了什么 漏了什么 验证了什么，取自轨迹里真实发生的工具调用和回复。
2. 有最终产物：最终提交里还存在什么问题，或者为什么确实完成。
3. 有可定位证据：至少落到具体对象，文件 函数 代码行 测试结果 轨迹行为。
4. 原分说得通：结尾写明给几分，并且这个分数能由前面已核实的事实撑住。

## 视角与语气

- 第一人称，站在提需求并亲手验过的人的角度写：我让模型做了什么 它做成了什么样 我实际跑出来看到了什么。
- 平实直接，像给同事说清楚这次的结论，不写成评测报告，也不刻意吐槽或卖萌。
- 不用审稿模板：不写评审方 验收方 本轮任务 原始轨迹 验收结论这类质检口吻，不用固定分栏，不套「先总结完成项 再列两项缺陷 最后说核心可运行但未达标」的套路。
- 不使用 markdown：不要标题 列表符号 加粗 代码块 表格。

## 标点与格式（硬性）

- 用空格代替标点，中文标点一律不用（，。、；：？！“”（）《》【】…— 等都不行）。
- 英文全部小写，包括文件名、函数名、报错、命令、产品名，例如 `date.py` `valueerror` `readme.md` `ffmpeg` `webgpu`。
- 文件名、路径、版本号、命令、数值中英文词内部的 `.` `/` `-` `_` `:` 可以保留，例如 `src/utils/date.py` `src/parser.py:82` `v22.23.2` `-16lufs` `localhost:20001`；但不能出现在词尾当句号或冒号用。
- 逗号、分号、括号、引号、问号、感叹号等英文标点一律不用；函数名不带括号，写 `parse_response` 不写 `parse_response()`。
- 中文与英文、中文与数字之间不加空格，例如「运行npm run dev后页面白屏」「延迟大概3秒」。
- 空格只用来断句：断句处的空格可以紧挨英文或数字（如「页面报typeerror 刷新也没用」）；但不要在英文或数字两边都加空格（「我点了 play 按钮」不行，应写「我点了play按钮」）。

## 推荐写法

用一段自然的话写完，大致顺序：

模型先做了【具体操作】 用【具体测试或轨迹行为】验证了【范围】 最终产物里【文件 函数 代码行】实现了【需求】 但【具体缺陷 或完成情况】会造成【用户或业务影响】 这个问题在最终提交里【仍然存在 或已经修好】 所以结合【过程表现 产物结果 验证范围】给【X】分

不需要写问题 证据 影响这类小标题。

### 5 分

写清楚改了哪个模块 怎么验证的 最终实现了哪些需求 测试结果与最终提交是否一致 为什么撑得起满分。不要为了凑格式硬编缺点，但也不能只写「功能完整 测试全过 表现优秀 给5分」这种没有具体对象的话。

### 1 到 4 分

必须同时写出过程问题和产物问题，每个产物问题都要有：

- 代码锚点：文件 函数 尽量带行号，如 `src/parser.py:82` 的 `parse_response`；
- 代码原因：哪段逻辑怎么错了，如没判断空响应就直接调用 `response.json`；
- 业务影响：用户会遇到什么，如批量导入在这条记录处整体中止；
- 最终状态：问题在最终提交里仍然存在。

界面报错 交互异常 功能缺失本身只算产物现象，必须追到代码原因；只说测试没做全而不说最终代码哪里错，也不够。

## 一定会被打回的写法

- 只有产物现象没有过程问题，例如只有页面抖动 接口报错 功能缺失。
- 只有过程问题没有最终产物问题，例如只说测试没做全。
- 只有文件名没有代码原因，例如只说 `parser.py` 有问题。
- 代码原因只写在证据清单或评分理由里，Feedback 原文没写。
- 用见原文 见文件与行号 同上 见上文之类的占位指代。
- 写测试通过 但实际没有执行对应断言；数量说过头，例如跑了200轮就说做了200次逐行比较。
- 中间失败后来修好了 却写成最终产物失败；要写清是中间版本的问题还是最终提交的问题。
- 把网络 api 代理 网关 平台超时或工具重跑写成模型的过程问题。
- 整体表现不错但仍有提升空间 建议修复 之类可以套到任何任务上的空话。

## 禁用表达

首先 其次 再次 综上 综上所述 总而言之 总的来说 值得注意的是 需要注意的是 需要指出的是 不难发现 显而易见 毋庸置疑 至关重要 赋能 一方面 另一方面 此外 与此同时 由此可见 整体而言 总体而言 具体而言 综合来看
